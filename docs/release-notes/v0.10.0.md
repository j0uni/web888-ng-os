**Running a receiver unattended:** the admin page shows the logs and
saves the settings to a file, the card's boot loader can be updated when
you ask, the bitstream setting on the admin page works, and there is a
guide for owners. With web888d v0.13.0. Test images, for owners who have
their Web-888 at hand.

**Updating from v0.9.0 or later:** the admin page's **Update** tab
offers v0.10.0 (it looks once a day, or press **Look for a release**):
**Install**, then **Reboot now**. The unit keeps its settings and goes
back to the previous system by itself if the new one doesn't come up
([docs/updates.md](https://github.com/jeskko/web888-ng-os/blob/v0.10.0/docs/updates.md)).

**From v0.3.0 to v0.8.0** (SSH, with an `ssh_key` in `web888.txt`):

```sh
rauc install https://github.com/jeskko/web888-ng-os/releases/download/v0.10.0/web888-ng-v0.10.0.raucb
reboot
```

Units on v0.1.0 or v0.2.0 write this card image instead (keep a copy of
`web888.txt`).

**New to web888-ng:** [docs/owner-guide.md](https://github.com/jeskko/web888-ng-os/blob/v0.10.0/docs/owner-guide.md).

## New since v0.9.3

* **The owner's guide**
  ([docs/owner-guide.md](https://github.com/jeskko/web888-ng-os/blob/v0.10.0/docs/owner-guide.md)):
  installing, coming from the stock firmware and going back, where each
  setting lives, updates, backups, what the unit connects to on the
  Internet and on your network, and what to do when it doesn't come up.
* **Logs** on the admin page: web888d's, the whole system's, the
  kernel's and the card's `web888-setup.log`, with a filter and a
  download. Also in safe mode.
* **Settings backup** (Configuration, **Backup**): one file with the
  admin page's configuration, the passwords (as hashes: keep it private)
  and the own frequency labels; **Restore from a file** puts them back,
  on this unit or a newly written card. `web888.txt`'s own settings
  (network, tunnels, SSH key) aren't in it: keep a copy of the file.
* **The card's boot loader** (`BOOT.BIN`, `u-boot.img`) can now be
  updated: each system carries its own copy, and **Update**, **Boot
  loader** (or `web888-bootloader install` over SSH) writes it to the
  card when you ask. Never by itself: the boot loader has no second copy
  to fall back to. **Be prepared to re-image the card** if something
  unexpected happens: download a settings backup first and have a card
  reader at hand. The old files stay on the card as `boot.bin.old` and
  `u-boot.img.old`, to rename back on a computer
  ([docs/updates.md](https://github.com/jeskko/web888-ng-os/blob/v0.10.0/docs/updates.md)).
  It writes only from a system that has started well, not in safe mode,
  and only on a card that booted with this image's own boot loader.
  * **Cards written before v0.9.3** get v0.9.3's boot loader this way,
    with its part of safe mode (a unit with no tries left in either
    system boots without the radio instead of trying again in a loop).
    Optional: the system runs fine with the old one.
* **The bitstream from the admin page:** without a `bitstream =` line in
  `web888.txt`, the admin page's setting now decides (Configuration,
  `radio.bitstream`: `auto`, the default, is the channelizer;
  `standard`; `channelizer`). A line in `web888.txt` still overrides it,
  as before. Units that never set either keep the channelizer.
* **Audio gaps** when web888d falls behind the hardware are now shown to
  listeners (the status bar's "gaps") and counted on the admin page.

**web888d v0.13.0**
([its notes](https://github.com/jeskko/web888-ng/releases/tag/v0.13.0)).

Nothing else changes: the same kernel, packages and bitstreams as
v0.9.3.

## Tested

In the emulator (web888-ng-hw `emu/tests/`), on this release's build:
* the image's boot through the boot ROM, both slots, `web888.txt`, safe
  mode, and **the boot loader update**: a card whose boot loader differs
  from the system's, written from the running system, its old file kept,
  and the unit booting with the new one (`sd-image.sh`), with no
  bitstream line and with `bitstream = standard`;
* **the update from the published v0.9.3 image to this release's bundle**
  (`ota.sh`), with a power cut mid-install and a bad update rolled back.

The new admin pages in a headless browser (desktop and phone).

On a Web-888: a tester's unit has run web888d v0.11.0 with the
channelizer from its card, the first card boot with
the channelizer on a board. This release's own additions have not run on
a board.

## Known limits

* The boot loader update has run in the emulator only. Writing it is
  optional; see above before you do.
* VHF (`band = vhf`) still needs testing against real signals or a signal
  generator (see v0.7.0's notes).
* The Update tab has installed updates in the emulator, not yet on a
  board; SSH (above) remains the way if it fails.
* Kiwi clients get levels in dBFS unless `[kiwi] smeter_offset_db` is
  set: the dBm calibration hasn't been measured yet.
* Safe mode has run in the emulator, not yet on a board.
* Assumes the usual 24.576 MHz reference for the ADC clock.
* Over plain HTTP the browser plays audio with about a quarter second more
  delay. The status bar links to the HTTPS address (the browser warns once
  about the unit's own certificate).
* No Wi-Fi since v0.9.1.
* The stock firmware's extensions and the Kiwi browser UI are not
  included.
