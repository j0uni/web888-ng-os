**Listener tools, Opus audio and propagation forecasts:** web888d
v0.15.0 sends a listener about a third of the data it did before (Opus
audio and a packed waterfall). It adds HF propagation forecasts, logs
what overloads the ADC, and gives the receiver an info page with its
privacy and licence details. Every CVE the scan finds in the image has
been assessed. Test images, for owners who have their Web-888 at hand.

**Updating from v0.9.0 or later:** the admin page's **Update** tab
offers v0.12.0 (it looks once a day, or press **Look for a release**):
**Install**, then **Reboot now**. The unit keeps its settings and goes
back to the previous system by itself if the new one doesn't come up
([docs/updates.md](https://github.com/jeskko/web888-ng-os/blob/v0.12.0/docs/updates.md)).

**From v0.3.0 to v0.8.0** (SSH, with an `ssh_key` in `web888.txt`):

```sh
rauc install https://github.com/jeskko/web888-ng-os/releases/download/v0.12.0/web888-ng-v0.12.0.raucb
reboot
```

Units on v0.1.0 or v0.2.0 write this card image instead (keep a copy of
`web888.txt`).

## New since v0.11.0

**web888d v0.15.0**
([its notes](https://github.com/jeskko/web888-ng/releases/tag/v0.15.0)):

* **Less data for each listener:** Opus audio (the default; mu-law and
  PCM remain) and a packed waterfall, 126 kbit/s in place of about 370.
  A data saver takes it to about 60.
* **Listener tools:**
  * waterfall palettes, peak hold, UTC time marks, a PNG snapshot;
  * frequency memories and VFO A/B;
  * WAV recording;
  * an IQ mode;
  * an audio spectrum panel;
  * an automatic notch for carriers;
  * key help.
* **Propagation forecasts** (Prop): VOACAP from 7 regions to the
  receiver, by hour and band, for SSB, CW and FT8. They work without a
  network too: the sunspot number comes from NOAA when the unit can
  reach it, otherwise from a built-in table.
* **ADC overload events** on the admin Status page and in the log: when,
  how long, and what caused each one (one carrier, with its frequency,
  or broadband).
* **The info page** (Info): the receiver's place, antenna and a photo,
  its limits, a privacy section, a reception notice, and the licences
  and credits.
* **Settings without a restart:** the RF attenuator, ADC dither and PGA.
  **Access limits:** banned addresses, minutes a day, and receivers for
  visitors without the password.
* **Less CPU** for each listener (a NEON FFT and other work), which
  leaves the skimmers more time.

**CVEs:** each CVE the daily scan reported in the image was checked
against what the image builds and runs. CVE_STATUS in the recipes
records why each one doesn't apply (for example, code that isn't built,
a program that isn't installed, or a flaw only root could reach). Five
remain open, all below CVSS 7.0: four in the 6.18 kernel (netlink,
futex, slab, ext4), which so far are fixed only in 7.2 and later, and
one in glibc's regcomp (only when memory runs out). The kernel, packages
and bitstreams are the same as in v0.11.0.

## Known limits

* VHF (`band = vhf`) still needs testing against real signals or a signal
  generator (see v0.7.0's notes).
* The Update tab has installed updates in the emulator, not yet on a
  board; SSH (above) remains the way if it fails.
* The boot loader update (v0.10.0) has run in the emulator only. Writing
  it is optional.
* Kiwi clients get levels in dBFS unless `[kiwi] smeter_offset_db` is
  set: the dBm calibration hasn't been measured yet.
* Safe mode has run in the emulator, not yet on a board.
* Assumes the usual 24.576 MHz reference for the ADC clock.
* Over plain HTTP the browser plays audio with about a quarter second more
  delay. The status bar links to the HTTPS address (the browser warns once
  about the unit's own certificate).
* No Wi-Fi since v0.9.1.
* The stock firmware's extensions and the Kiwi browser UI are not
  included.
